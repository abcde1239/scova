# Scova Agent Core

新执行先用模型知识提出候选答案、术语与原始文献线索，再按具体命题查证。规划冻结字段的核验类型：稳定知识、实时信息、精确数据或指定出处。综合通过 `fieldChecks` 区分已有材料待重绑、结构待修复、资料确实缺失和证据冲突：前两类使用现有原文修复，只有缺资料才按命题补搜，冲突保留双方。诊断和语义支持来自模型评估，原文区间及回执由程序认证。

Worker 为新执行冻结 `researchLoopPolicy: 1`。外部循环后仅允许稳定知识用已学知识补足解释，保存为独立 `model_answer`，前端显示【模型自回答】标签，不添加小字说明；实时信息、精确数据和指定出处继续要求外部核验。每批最多3个字段，结构错误最多修复一次，共用原 Run 预算与期限。自回答计入回答完成度，不生成网页、引用或外部支持，不推进完整基线。`coverage.metrics` 分别统计回答完成、外部证据支持和未解决问题；`coverage.propositions` 保存命题、字段绑定、条件及不可变正文 hash/UTF-16 引文区间。旧检查点与仅基于既有证据的修订保留原语义。

单一 LangGraph 研究图：加载固定任务、规划、搜索、选择来源、读取正文、校验、连续比较、综合和候选校验。输出带原文引用的 `AgentCandidate`，由 Worker 的领域服务负责报告交付。

Worker 新执行启用版本化的证据关联策略（`evidencePolicy: 1`）：规划在原调用内生成待核验的知识要点与核验目标；综合在原输入预算内查阅已读页，通过 `evidenceLinks` 保存跨问题的连续原文与支持理由。搜索的问题标签仅记录发现关系，原标签不改写；跨问题引用必须位于该次综合回执的合法关联片段中。Worker 对关联与模型回执一并认证，逐字引文、快照和条件要求保持有效；语义支持仍是模型评估。知识回退接收有界的已有答案、字段缺口、冲突与相关原文，仍保存为无外部引用的【模型自回答】。这些内容复用现有调用和预算，不新增模型节点；旧检查点和仅既有证据修订保留原策略。

新策略在综合的固定指令与 schema 估算超过阶段输入额度的80%时，压缩重复写作指令，保留冻结任务、问题、字段、会话及支持规则，为原文留出空间；仍超额则按原预算停止，不提高 Run 限额。

`runResearchAgent(context, dependencies)` 接收固定 owner/Run/版本/模式、预算和取消信号，以及受限工具、checkpointer 和引用提升接口。Agent 不持有数据库、队列、文件系统或脚本工具。新任务默认预算为 10 次搜索、20 次读取、600 秒、累计 1,000,000 输入 token 和 128,000 输出 token；实际值使用 Run 快照。

Worker 的新执行启用字段修复策略：检索前冻结每个成果的问题、对象和字段；按形式与问题范围分组，每组最多6项需求，单次4–24条结论（简报最多8条）。修复只请求尚未完整的字段，完整字段保持原绑定；局部修复失败不覆盖已有完整回答。原始尝试留在不可变回执中，最终活动结论由当前字段绑定重建，保留冲突证据，不反复累加历史尝试；活动集仍最多192条。稳定批次最多60组，原累计预算和deadline限制实际可执行次数。各批保存检查点，一组证据最多综合和修复各一次；仍未覆盖且预算允许时，定向补搜并读取最多4页，只有取得新正文才开启第二组综合，最多4轮。初始检索预留2次搜索和4次读取，直接回答先于历史变化提取。动态 schema 要求 assessment、形式、本批合法标识和单问题结论。0/N明确记录覆盖验收失败，部分材料不会冒充完整答复。旧检查点保留原策略。修复提示来自可信 schema，不复制无效响应值。

规划与综合接收首次启动时冻结的绝对查阅窗口，模型补入的冲突年份会被移除，用户明确要求的历史年份保留。候选按主题与未覆盖问题排序，每读取 3 个重新选择；搜索预算至少 4 次时预留最多 2 次补搜，同一规范 URL 不因重新选择重复读取。优先来源及冻结基线仍保留既有优先级。相关性是选排启发式，不能替代正文证据或发布时间核验。

综合采用软证据约束：逐字有据的内容保留为 `fact`，自己的话归纳为 `inference`；引用无法定位、问题对应不明或冲突证据不齐时，降为 `insufficient` 并记录待核实原因，不因单条问题放弃生成。原始响应留在账本，新策略的报告只保留当前字段绑定、冲突和无绑定问题的代表尝试。失配文字不保存成原文引用，没有直接引用的结论不会关联附录来源作为支持。结构错误或篇幅超限时每批最多定向修复一次；已有合法项保留。带引用的归纳计入问题回答覆盖，但不等于独立核验。`coverage.notes` 保存常规候选筛选说明，`coverage.gaps` 保存证据和时间等真实缺口；`coverage.research.uncertainClaims` 单列待核实条数。历史记录缺少这些可选字段仍可读取。

旧检查点的规划、比较、综合使用独立且可重放的阶段配额，计算与任务编辑器共用 `@scova/models` 预算策略。规划首次最多 4,000 token；比较按输出总额的六分之一、最多 24,000 token 作为分批基数，首次与修复按实际页数分配。默认 128,000 输出预算、10 页时，各个 3 页批首次约 9,599 token，尾页约 3,199 token。比较输入按累计输入预算的 30%、最多 192,000 token 分批，综合输入按 60%、单次最多 256,000 token；输出从规划、比较剩余额度中为首次和修复按 1:2 分配，分别封顶 32,000/64,000 token。新执行还会对结构错误及不完整覆盖计划使用唯一修复机会；旧规划在长度截断时以双倍额度重试一次，之后使用任务原文查询。Worker 账本仍检查实际剩余额度，失败调用有已确认 usage 时按实际结算，否则保留预留。旧 Run 的预算保持不变：需要更大预算时，编辑任务、保存新版本后新建执行，重试旧 Run 仍使用原版本预算。增加阶段额度不能保证完整生成，也不能解决网页访问拒绝或超时。内容按所选的简报、清单、对比或研究报告组织，不补充无关形式和章节；逐字原文保留为引用，综合失败不把正文前缀当作总结。综合优先使用完整采集正文，超出输入配额时传递分开的首、中、尾摘录并记录覆盖缺口；比较有单页前 32,000 字符的覆盖边界，仍服从阶段输入预算。

新覆盖策略按成功回执的实际输出用量和本轮剩余批次分配80%的剩余综合额度，首次封顶16k、修复24k；输入单次最多128k，为固定契约保留空间，再选择本批相容来源适配原文。未用完的成功预留可复用，unknown不退费。Worker 为每次供应商尝试原子预留预算，保存成功结果，并按稳定 operationKey 复用；不确定调用保留费用，恢复不重置用量或期限。不承诺供应商调用 exactly-once。每个节点保存 checkpoint 后先通过租约 fencing 提升明确引用，再继续执行；接管使用独立 epoch/thread，只复制已提升状态，丢弃旧线程可能迟到的 pending writes。

比较每批最多 3 页，各批共用原有比较额度；每批在截断或出现不合法事实时，最多对问题页紧凑修复一次。修复合计最多为首轮比较额度的两倍，仍从同一 Run 综合配额扣除，不增加总预算。合法事实独立保留，缺少原文支撑的值列为待核实变化线索；不伪造引用、不确认重要变化、不推进完整基线。每批成功结果随 checkpoint 保存，Worker 逐条与成功模型账本核对并重建清单；旧单次比较检查点仍可读取。明确模型额度不足时停止同一 Run 后续模型调用，已有材料仍可交付为 partial；补充额度后需新建执行。

搜索摘要不充当正文证据。读取失败的域名在后续选择中降序，候补仍消耗原有正文尝试预算；补搜按问题正文线索判断，不仅依赖查询继承的标签。系统校验新来源明确声明的带时区发布时间是否满足固定窗口，滚动窗口以 Run 首次开始时间固定；未知日期保留不确定性，窗口外资料作为背景参考，不冒充窗口内新发布事实。时间缺口不阻止其余结论生成。这不认证来源声明本身的真实性，官方身份仍须另行核验。

报告价值策略冻结任务问题，逐条记录问题关联、支持关系、来源关系、时间适用性和内容作用。确定性选择生成 `coverage.reportValue`：每个问题为 `supported`、`provisional`、`disputed` 或 `unresolved`，结论进入主回答、参考线索或省略。主回答需直接关联问题、有引用且自评为直接或部分支持；评估缺失按未知处理。摘要按核心问题、状态、条件和缺口排序，不因存在 inference 就排除关键事实。新执行按所有未覆盖问题推进补证；旧策略的可选补证仍最多一轮查询、两页正文并复用第二轮综合额度。

比较提取和报告综合的提示包含当前单次输出上限，并将完整 JSON 的软目标设为其 60%，比较最多 4,800、综合最多 8,192 tokens。优先保留核心答案、条件和必要引文，通过减少重复与次要条目控制篇幅；修复调用按本次额度重新生成提示。软目标只用于引导，不新增输出拒绝阈值；服务端预算、完整 JSON 校验和有界修复仍生效。

Worker 注入首次领取时冻结的合法基线，图优先重读基线来源；这些来源用于持续监测，首次发布时间不受后续发现窗口移动影响。先比较同 URL 的合法事实，再判断完整正文重复或明确次级来源关系。`comparison: completed` 表示已生成合法的部分或完整清单，不保证所有事实核验完成；未知、事实遗漏、输入截取或历史清单不可用仍保留 partial 和逐项说明。完全无比较结果与截止后确定性摘录使用 `not_performed`。

取消不产生交付；期限耗尽后只能从已合法保存的正文生成确定性 partial 候选。演示模式使用固定资料，真实模式缺配置明确失败。Worker 的交付服务负责复核已提升候选与工具账本，并原子保存报告、收件箱和终态；候选生成成功本身不等于 Run 已交付。
