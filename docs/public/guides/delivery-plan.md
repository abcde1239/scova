# Scova 分期交付计划

状态：2026-10-26。账号、任务、执行控制、搜索/模型/阅读适配器、持久化 Agent、证据报告交付、报告/收件箱 API、连续运行比较、时区调度与任务生命周期已实现；后端继续完善，前端暂缓。各阶段以门禁结束，未承诺上线日期；以下计划包含待实现目标。

基础 MVP 先交付可部署的查阅闭环、简报/增量、收件箱/站内提醒及可靠性门禁；原定完整 MVP 的收藏/笔记/搜索、反馈、其余三视图和报告问答独立跟踪，仍须在完整 MVP 关闭前验收。M5 因此分基础部署验收与补充功能验收，两者不以同一未完成状态互相遮蔽。

下面里程碑是交付顺序概览；Issue 的真实依赖按契约、数据和消费者关系组织，不把整阶段完成当成下一阶段所有工作的前置条件。前端遵循 [community 风格与 requestlane 约定](../reference/frontend-conventions.md)。

## 1. 里程碑与依赖

| 阶段                     | 交付内容                                                                                                                              | 进入下一阶段的条件                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |

| M2：账号、任务与执行骨架 | 会话账号、owner 授权、配置草稿/版本、手动执行、任务互斥、outbox、执行事件/SSE、中文页面框架                                           | 两账号隔离；重复点击/并发触发同一活动执行；SSE 断线回放无缺口                          |

依赖顺序为 M0 → M1 → M2 → M3 → M4 → M5。先做单进程内的清晰模块边界，再用 API/worker 两个进程拆分交互和执行；首版不引入多 Agent 服务、Kubernetes、专用搜索或向量集群。

## 2. 每阶段的具体工作

### M1：先验证高风险组合

1. 保留当前 Vite+ 1.4.0 与 pnpm 工作区方式，将模板前端迁到 apps/web 并接入 Vue 3、Router、Pinia、Vue Query、UnoCSS、naive-ui。
2. 新增有真实入口的工作区、共享 models、Drizzle schema 与迁移；更新 root scripts、tsconfig、harness 和 Vitest 扫描配置，不以空目录声称架构落地。
3. 在 Bun 中运行 Elysia、Drizzle PostgreSQL 事务、BullMQ 收发与连接关闭；固定兼容依赖版本并记录实验结果。
4. 验证 LangGraph PostgreSQL checkpointer：执行一节点、重启进程、从已提升 checkpoint 恢复；模拟旧 epoch 迟到写入，确认新 epoch 仍读取合法状态。
5. 验证所选时间库的 DST 策略，以及模型结构化输出/AbortSignal/usage 接口；不通过则先修适配协议。

测试交付：Vitest 图状态与 contracts 测试、真实 PostgreSQL/Redis 实验、两个进程接管测试。CI 在该阶段可先跑静态/单元测试，完整部署验证在 M5 补齐。

### M2：账号与执行事实源

完成注册登录注销、密码 hash 与会话失效、基础注册限流、owner 复合外键和服务层授权。实现任务编辑的乐观锁、不可变版本、计划预览、手动执行与 Idempotency-Key。

Run/Outbox/Event 和生产 consumer 已接通租约续期、有限接管、取消与终态事件；尚未接入 Agent 时明确失败，不生成占位报告。测试注入受控执行器验证故障和状态机。SSE 后续从数据库按 seq 读取，支持重连和最终状态刷新；页面继续按任务中心、创建编辑、执行详情和登录布局推进。

测试交付：跨用户集合/详情/写入/SSE 拒绝、外键越权、并发触发、数据库提交后队列不可用、发布后 dispatcher 崩溃、断线续传和编辑冲突。

### M3：检索、证据与首次成果

实现默认自部署 SearxNG、显式可选 Tavily 与远程模型适配层，HTTP/Readability、安全 URL/DNS/重定向校验。搜索/阅读可独立验证，上游失败记录覆盖缺口。实现预算预留/结算、有限循环、工具账本与 checkpoint 提升；完整研究缺必要配置时进入明确标识的全演示管线，运行失败不切换供应商。

首次完整执行建立基线和报告；先交付简报视图，底层结构支持后续其他视图。执行详情展示工具摘要、来源、用量和缺口，报告详情展示事实/推断/冲突/不足及引用。禁止把供应商失败吞成“没有变化”。

测试交付：超时、429/5xx/认证失败、预算耗尽、重启恢复、外部调用落库前崩溃、恶意网页指令、SSRF/DNS 重绑定与重定向、引用校验和演示隔离。真实烟测单独 opt-in，不由普通测试消耗密钥。

### M4：首要产品价值——两次运行

按固定案例实现规范 URL、稳定正文指纹、转载候选匹配、目标相关事实差异与 Baseline 推进。落实每日/每周时区计划、跳过重叠、停机最多补一次、取消与交付竞争、有限接管和用户重试新执行。

测试交付：[三个两次执行案例](../examples/two-run-scenarios.md)全部通过；再覆盖不完整运行不推进基线、配置语义变化、演示切换真实、重复投递、最终事务崩溃重试和旧 worker 迟到提交。每例断言分类、引用、基线、报告数量及提醒数量，不只测试界面有文字。

### M5：产品基础能力与可部署交付

完成反馈快照如何影响后续计划、收藏/纯文本笔记/历史、报告内基于已有证据的问答、需要新查阅时的关联执行；补齐清单、对比表、研究报告三种视图以及结果收件箱/设置。

Compose 提供同源 web/api、独立 worker、PostgreSQL/Redis 持久卷，迁移作为独立步骤；附 `.env.example`、真实与演示启动指南、健康检查、日志脱敏、清理策略、备份与恢复方法。GitHub Actions 运行相同治理入口、单元/集成/构建与 Playwright；公开 CI 不接生产密钥。

演示包包含三个预置任务、确定性两轮来源、运行截图或录屏、架构说明和真实运行步骤。简历只列已验证能力，并给出复现命令，不能把本文计划作为实现业绩。

## 3. 完整 MVP 发布门禁

- 三类任务可完成“创建 → 调度/手动 → 查阅 → 引用报告 → 二次差异”的全过程。
- `Idempotency-Key`、重复 job、恢复/重试和事务重放不重复保存报告、收件箱及提醒。
- 跨账号 API、SSE、资料、引用关系、checkpoint 和全文搜索均经过隔离测试。
- 不完整、失败、没有重要变化和演示模式有明确区分。
- 暂停、取消、DST、服务停机与预算上限有实际集成测试；没有依赖 `sleep` 猜测成功的测试。
- Docker Compose 在干净环境启动，健康检查通过，迁移可重复运行，备份能恢复。
- 所有事实型关键结论有可定位证据；示例和真实烟测分别报告结果，外部服务缺失不能计为真实检索通过。
- CI 使用与本地一致的验证任务，公开 README 只链接公开资料。

## 4. 验证层级与产物

| 层级      | 工具与环境                        | 覆盖重点                                      | 是否需要外部服务                 |
| --------- | --------------------------------- | --------------------------------------------- | -------------------------------- |
| 单元/状态 | Vitest（vp test）                 | 配置、规范化、差异、预算、状态与 contracts    | 否，固定 fixture                 |
| 集成/故障 | Vitest + Compose PostgreSQL/Redis | 唯一键、owner 外键、outbox、租约与 checkpoint | 本地基础服务                     |
| 用户流程  | Playwright                        | 两账号、任务/执行/报告、重连、反馈/收藏       | 本地 API/worker 与演示服务       |
| 真实烟测  | 显式脚本 + 本机实例/测试密钥      | SearxNG、远程模型、公共网页及可选 Tavily      | 是，搜索无需模型密钥，受预算约束 |

测试源代码保留在包内 `src/**/*.test.ts` 或 `tests/`；Playwright 放 `tests/e2e` 并设置独立配置。运行产物放 artifacts/coverage/playwright-report/test-results，不放进文档目录。每接入一个真实测试范围，更新 harness 的 covers 与 requireConfiguredTask；未配置不能写成 passed。

M0 只验证现有模板和治理接线；不运行未来业务的集成/E2E/真实烟测。架构、数据表和分期文档均为设计契约，后续实现发生变化时同步更新。
