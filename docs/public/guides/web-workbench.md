# Web 工作台

Scova 通过同源 Cookie 会话提供任务、收件箱和资料库。首版面向浏览器；桌面壳、本地一体化与完整实体移动端适配仍属后续范围。

## 当前功能

- 注册、登录、会话恢复、退出和账号偏好；四色主题、浅暗/系统与本地阅读设置。
- 账号独立的供应商与模型配置，支持多供应商保存和显式切换，见[Agent 配置](agent-configuration.md)。
- 任务列表、手工创建和编辑、自然语言可编辑草稿、周期与预算、执行 Agent 选择、暂停/恢复/归档及永久清除。保存配置不会立即执行。
- 点击启动真实研究，查看 Run 历史、实时进度、覆盖缺口、预算、取消与重试。关闭页面不等于取消服务端 Run。
- 同一报告的简报、主题清单、对比表和研究报告；证据引用、变化与报告历史，结果收件箱和站内通知，独立管理已读状态。
- 可撤销反馈及已交付效果、来源收藏、纯文本笔记、来源快照与历史、当前账号已存资料搜索。搜索资料库不会联网研究。
- 报告内证据问答；后续研究须再次明确确认，建立独立关联执行并沿用原版本、模式和预算。

生产报告通过“报告形式”在四种视图间切换，共用同一报告与全部保存证据，不启动研究或保存另一份报告。格式切换保留外围笔记和问答上下文，刷新以报告保存的形式初始化。图片组件目前用于受控样例，生产 DTO 没有媒体字段，缺图保持纯文字。完整业务旅程、视觉/键盘与浏览器 CI/ready 使用独立门禁；专项测试通过不代表未验证的远程研究或设备能力已完成。

正在查看的执行完成并取得报告入口后，自动进入报告阅读页；正文完整展示在前，问答、反馈、笔记及收藏等“阅读后继续”内容在后。历史执行详情保留独立入口，报告结果置于执行信息之前；报告页可返回“执行详情”查看日志、预算与覆盖说明。失败、取消或尚未找到报告时保留执行页，不跳转到无效报告。

创建或编辑任务时，可在“输出形式”下点击“查看输出示例”，预览简报、主题清单、对比和研究报告的大概布局。示例使用明确标注的虚构内容，预览不会修改表单或创建任务。

任务详情的“任务管理 → 清除任务”需在弹窗中确认，将永久删除任务配置、执行历史、报告及关联通知、报告笔记和问答，保留共享来源、网页快照和来源收藏。有活动执行时，须先取消并等待结束；归档任务也可清除。仅希望停止计划并保留历史时，可使用暂停或归档。

描述需求后，“生成任务草稿”会调用需求整理 Agent，根据原文和已有回答动态澄清搜索内容、来源、时间与交付形式。最多三轮，每轮最多三个问题；需求明确时可直接进入范围核对。问答和草稿生成共用独立解析限流与 Token 预算，不计入研究预算；失败保留当前输入，可重试或手工继续。模型不可用时明确显示手工回退，不提供伪装成 AI 的固定问题。

核对核心问题与排除内容、查阅时间与来源、研究方式及输出形式后，再生成最终草稿。模型不能扩大已确认范围，草稿仍须应用到表单并保存才会创建任务。“手动填写”停止在途解析、保留原文与已有配置，并聚焦下方任务标题，可随时返回 AI 整理入口。固定日期使用日历选择，执行当地时间使用时分选择器，也可键盘输入。预算分配表和详细解释通过“查看预算说明”弹窗按需查看，预算输入和校验错误直接显示在表单。

任务的“已启用”表示允许后续计划，不代表当前正在执行。单次执行另有排队、运行、恢复、取消中及已完成、有结果、失败、已取消等状态；暂停只停止未来计划，归档会阻止新执行并请求取消在途执行。

报告和已结束的执行优先展示内容交付情况：“核心问题已回答”表示核心问题均有引用支撑的答案；“已生成部分答案”表示已回答部分问题；“已保存来源资料”表示目前仅有可查阅的材料。适用条件、不同观点或未知发布时间不会抹掉已有答案，引用和限制继续保留。此分类独立于严格查阅完整度；范围尚不完整时仍可阅读报告，但不能据此断言无重要变化或推进完整比较基线。同一工具操作重试成功后，已恢复的旧故障只留说明，累计用量照常保留。

引用分别展示来源声明的发布时间和更新时间，可识别页面元信息、关联本文的结构化数据及明确标记的正文时间。只有日期或没有时区时保留原精度，不补造午夜 UTC；时间窗口边界无法确定时保留待确认。更新时间、网页采集时间和搜索摘要不替代发布时间。

创建或编辑时可选“资料收集”或“分析研究”。资料收集汇集当前读取的内容，不因缺少发布时间要求额外论证，也不声称资料在查阅窗口内新发布；分析研究继续检查时间适用性、条件与支持关系。两种方式均保留引用、真实缺失项和来源冲突。执行前的“本次输出形式”可选择简报、主题清单、对比表或研究报告，仅影响这次新执行，重发同一命令保持原选择。

执行日志区分 warning 与 error：单页拒绝访问、失效、限流、无法提取正文等可跳过问题显示警告，并给出处理建议；配置、安全校验、模型余额及最终执行失败显示错误。临时网络与网页服务端故障最多重试一次，共用原时间及累计读取预算；不重试登录限制、验证码、404或429。仅支持可直接读取的 UTF-8 HTML，动态页面或文件可换用公开正文页；全部来源不可用时明确失败，不生成空报告。

## 开发与验证

在仓库根运行：

```sh
vp install
vp run dev:frontend
```

API/Worker、数据库、Redis 与搜索配置见[部署指南](deployment.md)。`vp run dev:frontend` 仅启动 Vite；`vp run dev` 并行启动前端、Server 和 Worker。开发通过根 `.env.local` 的 `VITE_API_BASE_URL` 直连 API，`APP_ORIGIN` 配置准确的前端来源，保留 Cookie 与 CSRF 约束，详见[本地开发](local-development.md)。完整同源部署使用 Compose。缺少远程模型时草稿可手工编辑、报告问答明确提示不足；live 不自动切换为演示。

```sh
vp check
vp test
vp run build:frontend
vp run preview:frontend
vp run test:e2e tests/e2e/shell.spec.ts
vp run verify:web
vp run verify:mvp-full
```

生产构建只有正常应用入口；组件样例与额外测试 HTML 仅在 test 构建生成，生产报告路由本身已支持四形式。浏览器安装、领域配置、隔离全栈环境及证据边界见[浏览器测试](../reference/browser-testing.md)和[完整工作台验收](../reference/workbench-verification.md)。实体设备、读屏和真实远程模型需分别验证。

`vp run build:e2e` 生成含组件样例的 test 构建，同样写入 `apps/web/dist`；切回普通预览前执行 `vp run build:frontend`。`vp run preview:frontend` 仅预览现有静态产物，API 地址由构建时的 `VITE_API_BASE_URL` 决定。根目录 `vp run build` 按依赖顺序执行整个 monorepo 的 build，`vp -C apps/web preview` 可显式指定前端工作区。
