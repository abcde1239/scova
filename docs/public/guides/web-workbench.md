# Web 工作台

Scova 通过同源 Cookie 会话提供任务、收件箱和资料库。首版面向浏览器；桌面壳、本地一体化与完整实体移动端适配仍属后续范围。

## 当前功能

- 注册、登录、会话恢复、退出和账号偏好；四色主题、浅暗/系统与本地阅读设置。
- 账号独立的供应商与模型配置，支持多供应商保存和显式切换，见[Agent 配置](agent-configuration.md)。
- 任务列表、手工创建和编辑、自然语言可编辑草稿、周期与预算、执行 Agent 选择、暂停/恢复/归档及永久清除。保存配置不会立即执行。
- 点击启动真实研究，查看 Run 历史、实时进度、覆盖缺口、预算、取消与重试。关闭页面不等于取消服务端 Run。
- 同一报告的简报、主题清单、对比表和研究报告；证据引用、变化与报告历史，结果收件箱和站内通知，独立管理已读状态。
- 报告页支持「导出 Markdown」和「导出 JSON」。两种格式均提供摘要、覆盖缺口、结论、变化及引用片段。JSON 为带版本号的结构化文档。导出使用已交付报告，无需重新运行研究。两种格式的暂存均限制在当前账号内，有效期 24 小时，单份上限 256 KiB，账号总计最多 32 份。同一报告和格式在有效期内可复用。
- 成果面板的「打印 / 另存为 PDF」会打开浏览器打印，包含当前成果、变化和来源。报告附件支持上传、下载和删除 CSV、UTF-8 TXT 和 PDF，单文件最多 256 KiB。CSV 和 TXT 可按原文行预览，PDF 提供原件下载。
- 工作流支持串行和并行研究组。编辑器可用按钮把相邻阶段合为并行组，也可把单个节点拆出。发布冻结图与任务版本。同组各自启动研究执行，全部成功后进入下一阶段，取消会等待活动子执行收敛。
- 可撤销反馈及已交付效果、来源收藏、纯文本笔记、来源快照与历史、当前账号已存资料搜索。搜索资料库不会联网研究。
- 报告内连续证据问答、逐轮补查与资料内改写；原位确认计划后建立独立执行，沿用原版本、模式和预算。可选择续作与原报告合并，生成新的独立成果。

生产报告只展示实际保存的成果形式。简报、主题清单、对比表和研究报告可有各自的内容与证据索引；阅读切换不会启动研究或补生成其他形式。格式切换保留外围笔记和问答上下文，刷新以报告保存的形式初始化。图片组件目前用于受控样例，生产 DTO 没有媒体字段，缺图保持纯文字。完整业务旅程、视觉/键盘与浏览器 CI/ready 使用独立门禁；专项测试通过不代表未验证的远程研究或设备能力已完成。

正在查看的执行完成并取得报告入口后，自动进入报告工作区。宽屏左侧为连续对话，右侧为成果浮窗；窄屏先展示对话，点击“成果”进入全屏阅读，用“返回对话”或 Escape 返回并保留草稿和滚动位置。桌面浮窗通过 × 关闭，“完整阅读”展开同一面板。历史执行详情保留独立入口，报告结果置于执行信息之前；失败、取消或尚未找到报告时保留执行页。

Enter 发送普通提问，Shift+Enter 换行。内容建议会填入草稿。对正式报告，可以从输入区选择“补查新资料”，核对问题、搜索方式、预算和成果形式后启动研究。可选内置搜索或已配置的账号 Search API。取消确认会保留草稿。同一网页的引用集中在每轮回答末尾，可展开逐字引文和保存定位。每轮回答下方可选择“据此补查新资料”或“用已有资料改写”，在原位计划中选择成果形式、核对费用和预算后开始；搜索方式沿用原执行配置。进度来自实际执行事件，停止、重试和详情均连接真实 Run。结果未确认时保留原请求标识，通过恢复入口确认，避免重复建立执行。

后续成果均为独立报告，成果选择器注明来源轮次；切换阅读成果时，讨论仍以原报告为上下文。“合并到原报告”可选择最多 8 份同一对话的续作，使用保存证据生成新的合并报告，不联网，计入模型额度，原报告和续作保留。初次任务的配置、周期、时区和预算仍在任务页面管理；报告页的“修改定期研究设置”直接进入原编辑页。

创建或编辑任务时，可在“输出形式”旁点击 ⓘ 图标，预览简报、主题清单、对比和研究报告的交付样例。示例使用明确标注的虚构内容，预览不会修改表单或创建任务。

任务详情的“任务管理 → 清除任务”需在弹窗中确认，将永久删除任务配置、执行历史、报告及关联通知、报告笔记和问答，保留共享来源、网页快照和来源收藏。有活动执行时，须先取消并等待结束；归档任务也可清除。仅希望停止计划并保留历史时，可使用暂停或归档。

任务列表可通过“批量管理”多选并清除，每批最多 50 个，仅限当前筛选下已加载的任务；加载更多不会自动选中，切换筛选清空选择。清除前重新核对所选任务，弹窗列出任务名称、数量和影响，并要求输入“清除 N 个任务”。有活动执行或修订变化的任务保留；结果逐项展示，可能只完成部分清除。网络结果不明时停止后续请求且不自动重发，可用“刷新任务列表”核对后重新选择。

描述需求后，“生成任务草稿”会调用需求整理 Agent，根据原文和已有回答动态澄清搜索内容、来源、时间与交付形式。最多三轮，每轮最多三个问题；需求明确时可直接进入范围核对。问答和草稿生成共用独立解析限流与 Token 预算，不计入研究预算；失败保留当前输入，可重试或手工继续。模型不可用时明确显示手工回退，不提供伪装成 AI 的固定问题。

核对核心问题与排除内容、查阅时间与来源、研究方式及输出形式后，再生成最终草稿。模型不能扩大已确认范围，草稿仍须应用到表单并保存才会创建任务。“手动填写”停止在途解析、保留原文与已有配置，并聚焦下方任务标题，可随时返回 AI 整理入口。固定日期使用日历选择，执行当地时间使用时分选择器，也可键盘输入。预算分配表和详细解释通过“查看预算说明”弹窗按需查看，预算输入和校验错误直接显示在表单。

任务的“已启用”表示允许后续计划，不代表当前正在执行。单次执行另有排队、运行、恢复、取消中及已完成、有结果、失败、已取消等状态；暂停只停止未来计划，归档会阻止新执行并请求取消在途执行。

报告和已结束的执行分别展示回答完成、外部证据支持和未解决项。分析研究允许稳定知识以【模型自回答】交付，无引用，也不计入外部支持；资料采集不使用模型补答。回答完成不代表已满足比较条件，新执行只有必答字段全部获得外部支持并通过完整性与比较检查，才能推进比较起点。具体规则见[研究循环](../reference/agent-research-loop.md)。同一工具操作重试成功后，已恢复的旧故障只留说明，累计用量照常保留。

报告正文和结构化字段用小字号来源标签显示站点名；`+N` 表示还关联 N 个不同网页。打开标签可查看已保存的引用摘录、访问原网页或跳到文末原文定位，不会重新读取网页。文末「来源与保存引用」仍保留完整的版本与引用。

引用分别展示来源声明的发布时间和更新时间，可识别页面元信息、关联本文的结构化数据及明确标记的正文时间。只有日期或没有时区时保留原精度，不补造午夜 UTC；时间窗口边界无法确定时保留待确认。更新时间、网页采集时间和搜索摘要不替代发布时间。

创建或编辑时可选“资料采集”或“分析研究”。资料采集只收录日期在窗口内、值有直接原文出处的条目，默认近 7 天；日期未确认的来源默认单列且不计入结果，也可选择直接剔除。分析研究综合证据和推论，允许标注模型回答，也可选择不限日期。来源发布时间优先，仅当它未知时才使用独立解析的更新时间；采集时间不能替代来源日期。两种方式均保留真实缺失项和来源冲突。输出形式在任务配置编辑页修改并保存，立即执行沿用任务配置，重试保留原执行形式。

任务配置还可保存“搜索方式”：“Search API（搜索与网页读取）”使用账号独立保存的 API 完成搜索与正文读取；“内置 SearXNG＋网页读取工具”使用系统搜索服务并读取来源网页。“沿用账号搜索配置”读取账号搜索区域的默认方式，不随执行模型变化，也无服务器搜索默认。立即执行默认沿用任务搜索方式，也可仅为本次执行覆盖；重试未覆盖时沿用原执行的搜索方式。发送后同一命令重发保持原选择，缺少指定服务配置会明确失败，不自动切换搜索方式。

执行日志区分 warning 与 error：单页拒绝访问、失效、限流、无法提取正文等可跳过问题显示警告；配置、安全校验、模型余额及最终执行失败显示错误。SearXNG 本地 Reader 对临时网络与网页服务端故障最多重试一次，共用原时间及累计读取预算；不重试登录限制、验证码、404 或 429。Search API 远程读取默认单次调用，失败不切换本地 Reader。支持的来源格式见[搜索与读取](search.md)。没有可交付内容时执行失败；资料采集若只有已认证的日期筛选说明，仍可部分交付“0 收录”，这不表示互联网没有相关资料。

模型错误分别显示 JSON 无效、报告结构不符、响应状态异常或拒绝生成；结构错误会在原修复次数和预算内重新生成。两次综合均失败但已有可验证正文时，保留为“已保存来源资料”的部分交付，各所选形式明确显示不足，不计为完成研究。失败响应有可信用量时按实际值计量；超时或无法确认用量时保留预算预留，日志标记“保守估算”，不表示供应商已确认扣费。

## 界面语言

登录页及工作台顶部可切换简体中文 / English，默认简体中文，选择仅保存在当前浏览器。首批覆盖导航、页面标题、登录注册及通用连接状态，任务、报告等业务页面正文尚未完全翻译。此选项不修改账号或任务时区、不决定搜索语言或地区，也不翻译报告与原文引文。

## 开发与验证

在仓库根运行：

```sh
vp install
vp run dev:frontend
```

API/Worker、数据库、Redis 与搜索配置见[部署指南](deployment.md)。`vp run dev:frontend` 仅启动 Vite；`vp run dev` 并行启动前端、Server 和 Worker。开发通过根 `.env.local` 的 `VITE_API_BASE_URL` 直连 API，`APP_ORIGIN` 配置准确的前端来源，保留 Cookie 与 CSRF 约束，详见[本地开发](local-development.md)。完整同源部署使用 Compose。缺少远程模型时草稿可手工编辑、报告问答明确提示不足；live 不自动切换为演示。

```sh
vp check
vp test
vp run build:frontend
vp run preview:frontend
vp run test:e2e tests/e2e/shell.spec.ts
vp run verify:web
vp run verify:mvp-full
```

生产构建只有正常应用入口；组件样例与额外测试 HTML 仅在 test 构建生成，生产报告路由本身已支持四形式。浏览器安装、领域配置、隔离全栈环境及证据边界见[浏览器测试](../reference/browser-testing.md)和[完整工作台验收](../reference/workbench-verification.md)。实体设备、读屏和真实远程模型需分别验证。

`vp run build:e2e` 生成含组件样例的 test 构建，同样写入 `apps/web/dist`；切回普通预览前执行 `vp run build:frontend`。`vp run preview:frontend` 仅预览现有静态产物，API 地址由构建时的 `VITE_API_BASE_URL` 决定。根目录 `vp run build` 按依赖顺序执行整个 monorepo 的 build，`vp -C apps/web preview` 可显式指定前端工作区。
