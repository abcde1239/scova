# Agent 与模型配置

新任务默认执行预算为10分钟、累计输入1,000,000／输出128,000 token，可在任务配置中调整；部署上限为30分钟、累计输入2,000,000／输出512,000 token。规划、比较、综合及重试共享累计预算，单次输入最多256,000，综合首次最多输出32,000、修复重试最多64,000 token，模型调用最多等待120秒。供应商和所选模型仍可能有更低的上下文或输出限制。已保存任务保留原预算，修改并保存后仅影响新版本及后续执行；调整后重新执行，已有报告不自动改写。简报优先归纳核心发现，原句保留为引用；无法完成综合时明确显示未完成归纳，不将正文摘录当作总结。

登录后进入「账号 → Agent 配置」（`/account/agent`）。每个账号独立保存供应商、接口地址、模型 ID 和 API Key；同一账号可保存多项，为「需求整理」和「研究执行」分别选择模型，也可共用同一项。

## 添加与切换

页面分为上方「模型选择」与下方「供应商管理」：前者显示当前选择并切换用途，后者集中添加、编辑和删除配置。

1. 在「供应商管理」点击「添加供应商」，选择预设或自定义配置。预设填写地址与协议。
2. 填写配置名称、API 根地址和 API Key，点击「获取模型列表」，按名称或 ID 搜索并选择模型，然后保存。根地址包含版本路径，例如 `https://api.example.com/v1`，无需加具体请求接口。
3. 在上方「模型选择」分别选择「需求整理使用的配置」与「研究执行使用的配置」，选择后即保存该用途。需求整理负责生成任务草稿，研究执行负责 live 研究和报告问答；一种用途的切换不会改动另一种。后续调用以及新开始或中断恢复的研究读取对应配置；当前执行会话保持启动时的配置。切换期间或编辑配置时暂时禁用用途选择，失败后重新读取实际配置。

| 接口协议                  | 使用场景                                               |
| ------------------------- | ------------------------------------------------------ |
| OpenAI 兼容 · JSON Schema | 支持 Chat Completions 严格结构化输出的模型或兼容服务   |
| OpenAI 兼容 · JSON 模式   | 支持 `json_object` 的兼容服务，DeepSeek 预设使用此模式 |
| Anthropic Messages        | 通过工具调用返回结构化结果                             |
| Gemini generateContent    | 通过 JSON Schema 返回结构化结果                        |

所有模式仍校验返回数据、完成状态和用量；不合格结果不会进入报告。兼容服务需支持选定协议，保存成功只代表配置已保存，不代表远程模型已验证。保存和切换均不调用收费模型，不自动尝试其他供应商。

模型列表显示读取中、成功数量、空列表或失败状态，可刷新和重试；读取只访问供应商目录，不生成内容、不保存配置或切换用途。编辑已有配置会使用本人已存密钥自动读取；更改地址或协议后需重新填写密钥，防止将原密钥发送到新目的地。改连接或关闭编辑会取消旧读取，迟到结果不会覆盖新状态。

OpenAI 兼容与 Anthropic 读取各自根地址下的 `/models`，Gemini 读取支持 `generateContent` 的模型；分页或数量达到上限时明确提示仅显示部分结果。目录可见不保证模型支持所选的结构化输出协议。若服务不提供目录、私有模型未列出或列表为空，可展开「手动输入模型 ID」。刷新不会自动替换已选模型，旧配置在目录中未返回时保留并明确标注。

模型列表和实际生成共用解析策略。默认 `MODEL_DNS_RESOLVER=auto` 使用系统DNS；系统全部返回代理Fake-IP（`198.18.0.0/15`）时，通过固定公网IP连接AliDNS的HTTPS服务重新解析，再校验和固定真实公网IP。不会直接放行Fake-IP、内网或混合解析，DNS查询不携带API Key。可设置 `system` 禁用回退，或显式选择 `alidns`、`cloudflare`、`google`；修改后重启Server/Worker。网页读取使用独立的 `READER_DNS_RESOLVER`（默认 `auto`，可选值相同），不继承模型通道配置；固定SearXNG服务地址继续使用独立内部服务连接策略。

读取失败时，页面区分供应商拒绝鉴权、不提供目录、网络连接、超时、响应格式、大小限制与限流等原因。排查时可提供失败请求 Response 中的 `code`、`message` 和 `requestId`；无需发送请求体、Cookie 或 API Key。`MODEL_CATALOG_NETWORK` 检查代理、DNS 与 TLS；`MODEL_CATALOG_INVALID_RESPONSE` 检查根地址和协议；`MODEL_CATALOG_TOO_LARGE` 可先用手工模型 ID，大小限制仍保留。

编辑时密钥留空保留原值，填写新密钥则替换。密钥不会回显；切换预设会清空未保存的模型 ID 和密钥。编辑、切换和删除都校验修订号，多窗口冲突时重新读取后操作。保存结果未知时先关闭编辑并重新读取列表，避免重复创建。

某一用途未启用个人供应商时，该用途使用部署的 `MODEL_API_KEY`、`MODEL_NAME`、`MODEL_BASE_URL` 默认配置。删除配置时，正在使用它的用途恢复默认选择；未配置默认模型时，live 不可用，草稿和问答沿原有缺模型流程处理。新执行统一真实研究，不再提供 demo 入口；历史演示报告仍可查阅。

## 管理员设置

Server 和 Worker 必须配置相同的 `AGENT_CREDENTIAL_KEY`（64 位十六进制、256 bit 随机密钥），用于加密账号 API Key。本机执行 `vp run local:init` 会为缺失配置初始化一次，并保存在被忽略的根 `.env.local`；部署在 `.env` 配置，Compose 会同时传入两个服务。

升级先备份、停止应用，再执行增量迁移；本机为 `vp run db:migrate`，Compose 见[部署指南](deployment.md)。迁移新增供应商表与独立用途选择，不重置现有数据。已有启用配置升级后继续兼任两种用途，可随后分别切换。

保管并单独备份加密主密钥，升级时保持不变；只有数据库备份而没有原主密钥，无法恢复已保存的账号 API Key。未配置主密钥时可查看和删除配置，无法新增、编辑或切换。接口仅允许公开 HTTPS 地址，保留 DNS、公网地址与重定向约束。

## 任务多项输入

任务新建和编辑中的关注点、排除条件、优先来源网址和排除来源网址均逐项填写，可独立添加、修改和删除。Enter 新增一项，文本项用 Shift+Enter 换行；逗号和项内换行不会自动拆项。已有配置和自然语言草稿按原数组保留，每个链接独立校验，保存任务仍不立即执行。
