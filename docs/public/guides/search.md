# 搜索服务配置

研究需要搜索来源。Scova 的搜索与正文提取由账号独立配置，与解析、任务执行的模型分开保存。服务器不提供默认的搜索 Agent 或搜索 API 密钥。

## 选择搜索方式

| 方式             | 搜索                        | 读取正文                                    | 适合                     |
| ---------------- | --------------------------- | ------------------------------------------- | ------------------------ |
| Search API       | DeepSeek 或 Tavily          | 同一 API 提取                               | 不想部署搜索服务         |
| 自托管 SearXNG   | 本机或部署者提供的 SearXNG  | 本地 Reader；部署者也可启用 Firecrawl Cloud | 想免费、自己控制搜索     |
| 自定义 HTTP JSON | 你自己的公网 HTTPS 搜索接口 | 本地 Reader                                 | 已有搜索服务，例如 Brave |

两种内置方式都没有配置时，工作流模板仍可使用，但研究任务会因缺少搜索而失败。

## 使用 Search API

在「账号 → Agent 配置 → 搜索与正文提取」选择 Search API，填写协议、HTTPS API 根地址和独立密钥。搜索和正文都由同一个 API 服务提供。

| 协议     | API 根地址                  | 搜索与读取接口              |
| -------- | --------------------------- | --------------------------- |
| deepseek | https://api.deepseek.com/v1 | tools/search 与 tools/fetch |
| tavily   | https://api.tavily.com      | search 与 extract           |

- **兼容服务**：账号 API 地址可以填兼容服务的 HTTPS 根地址（含版本或路径前缀，省略具体接口），但必须同时实现所选协议的搜索和读取接口。
- **Perplexity**：暂无独立的网页读取接口，当前不可选。
- **费用**：接口可能另行计费。搜索密钥不会继承 `MODEL_API_KEY`。
- **搜索词长度**：DeepSeek 最多 128 个 Unicode 码点，Tavily 最多 2,000 个，过长会明确失败。
- **保存**：只保存配置，不会调用搜索或模型接口；解析与报告问答也不会因此自动联网。
- **密钥**：单独加密保存，接口只返回 `hasApiKey`。同协议、同地址编辑时可留空保留；更改协议或地址必须重新填写密钥。
- **与模型的关系**：切换、编辑或删除模型供应商不会改变搜索配置。切换到 SearXNG 会保留 API 配置，方便任务显式使用 API。

### 在任务里选择搜索方式

- **Search API／自定义搜索（沿用账号读取方式）**：使用账号保存的搜索服务和读取方式。DeepSeek/Tavily 由同一 API 提取正文，自定义 JSON 服务使用本地 Reader。
- **内置 SearXNG＋网页读取工具**：使用系统搜索服务并读取来源网页。
- **沿用账号搜索配置**：读取账号的默认方式；账号未设置时使用内置 SearXNG。立即执行时可以临时覆盖。

读取失败不会自动切换方式。显式选择 API 却没有保存密钥时，会提示配置 API 或改用内置搜索，不会用模型密钥或环境变量代替。

报告中的「待补充」不一定是搜索引擎的问题，也可能来自查询未命中目标、原站不可读、模型输入只覆盖部分正文，或生成的答案没有覆盖所需字段。

### 搜索慢或失败时

查看执行时，内置搜索等待超过 15 秒，或出现搜索 warning/error，会显示可关闭的提示，并提供 Search API 配置入口。同一次查看只提示一次，不会自动切换服务，也不阻止继续使用 SearXNG；回放历史日志时不会重复提醒。

### 搜索语言

Agent 会按原始资料选择搜索语言。发现对象混淆、原始来源缺失等字段缺口时，可以改写搜索词、保留对象和版本并调整语言，报告仍使用中文。

- **Tavily**：接收语言偏好。
- **DeepSeek**：使用改写后的原文语言查询。
- **SearXNG**：逐条接收语言参数。

纠偏共享原有的搜索、读取、模型和时间预算；重复方向或连续没有有效字段增益会停止。换语言不能保证解决登录墙、403 或日期未知。

### API 网页读取

- **采用的正文**：DeepSeek 只采用 `content`，Tavily 只采用 `raw_content`。snippet、summary、Tavily 搜索的 content 和生成答案都不作为正文。
- **读取方式**：已有非空、未被本地裁剪的 API 正文通过读取阶段校验后保存；缺失或被裁剪时，用同一 API 的 Fetch / Extract 读取指定 URL。显式指定的优先来源也可以直接远程读取。
- **不回退**：API 模式不访问原站核实，不调用本地 Reader，也不会因网络、HTTP 或提取失败回退到本地工具。取消、URL 安全、租约和预算错误照常传播。
- **证据范围**：API 提取保留 `search-api` 来源标识。正文非空、哈希匹配或未被本地裁剪，都不代表已证明整页覆盖；不同快照不会拼接成全文，API 给出的日期也不当作已核实的页面发布时间。
- **缓存**：复用已提交的读取结果不会再次联网，也不会重复计页。

### 网络与限额

- **DNS**：部署的 `SEARCH_DNS_RESOLVER=auto` 只管理 API 的网络解析，保留公网校验与 Fake-IP 可信解析，可选 `system`、`alidns`、`cloudflare`、`google`。它不选择搜索服务，也不保存凭据。
- **请求**：禁止重定向，默认不重试或切换渠道。Worker 每次搜索请求计一次搜索，最多保留 10 条候选；远程提取请求计入读取预算。
- **读取时限**：DeepSeek/Tavily 远程读取最多 45 秒，本地 Reader 与普通搜索最多 15 秒，并受执行剩余时间和页面、尝试预算限制。
- **大小限制**：每次 HTTP 响应上限 2 MiB。搜索账本保留的正文每页最多 100,000 个 Unicode 码点，合计最多 800,000 UTF-8 字节；远程单页读取最多保留 1,000,000 个正文字符。局部裁剪另有标记。

协议参考：[DeepSeek Search](https://api-docs.deepseek.com/api/search)、[DeepSeek Fetch](https://api-docs.deepseek.com/api/fetch)、[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)、[Tavily Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)。Perplexity 的 [Fetch URL 工具](https://docs.perplexity.ai/docs/agent-api/tools/fetch-url-content)属于另行计费的生成式 Agent API，当前不作为独立 Search API 读取使用。

### 从旧配置迁移

- **迁入搜索 API**：如果搜索 API 原来保存在某个模型配置里，在该区域点「迁入」复制为账号搜索配置。迁入后与原模型无关联。
- **移除旧环境变量**：`SEARCH_PROVIDER`、`SEARCH_API_*` 和 `TAVILY_API_KEY` 不再作为服务器搜索配置读取，请从部署文件移除。
- **升级**：需要先执行增量数据库迁移。

## 自托管 SearXNG

### 启动

需要 Docker Desktop（Windows 使用 Linux 容器），或 Linux Docker Engine + Compose。

随 Scova 基础服务一起启动（本地开发推荐）：

```sh
vp run local:up --search
```

PostgreSQL、Redis、SearXNG 会一起启动，搜索地址为 `http://127.0.0.1:18080`，配置统一在根 `.env.local`，见[本地开发环境](local-development.md)。

只启动搜索的独立方案使用自己的配置、端口和 Compose 项目，在仓库根目录执行：

```sh
vp install
vp run search:up
vp run test:search:live
```

- **配置文件**：启动命令会自动创建被 Git 忽略的 `.env.searxng`，生成随机实例密钥，已有文件会保留。
- **访问**：浏览器打开[本机搜索](http://127.0.0.1:8080)。
- **端口冲突**：修改 `.env.searxng` 中的 `SCOVA_SEARXNG_PORT` 后再次启动，并把调用方的 `SEARXNG_BASE_URL` 设为对应地址。

```sh
vp run search:status
vp run search:down
```

`search:down` 只移除本项目的搜索容器和网络，保留缓存卷与本地配置。该部署不影响 Scova 的 PostgreSQL/Redis 测试服务。

### 资源与访问

- **容器**：一个 SearxNG 容器、一个 worker、两个阻塞线程，限制 1 CPU、512 MiB 内存，日志轮转。
- **定位**：关闭公共实例特性与限流，不额外启动 Valkey，仅用于个人低并发。端口只绑定 `127.0.0.1`。
- **不含**：Docker Desktop 自身，以及 Scova 的数据库、Worker 和模型，不计入该资源上限。
- **镜像**：固定为 `2026.10.24-ef0ec03da`，Compose 使用镜像摘要。升级时更新摘要，并重新验证 JSON API 和实际搜索。

### 搜索引擎与语言

配置在 `ops/searxng/settings.yml`：

- **默认语言和地区**：`zh-CN`，Agent 可逐条传入搜索语言。
- **启用的引擎**：Bing、DuckDuckGo 与 Google CSE，开启 HTML/JSON，只查询第一页并限制引擎超时。
- **Bing**：当前出口的 `www.bing.com` 会重定向到中国网关，因此通过固定的 `cn.bing.com` 网关访问，并采用请求的语言和地区。英文查询使用 `ensearch=1`，其他语言使用 `ensearch=0`。小型 `bing_international.py` 适配层以只读文件挂载，复用固定镜像的原生请求构建与结果解析，不修改其他引擎的地区。
- **暂时禁用**：Brave（当前出口返回 429）和普通 Google（适配器返回 403）。
- **Google CSE**：使用 SearxNG 自带的 `google cse` 适配器，无需 API Key。它通过 CSE 网页接口和配置的 CX 获取结果，默认使用第三方 CX，不是官方 Custom Search JSON API，也不保证标准 Google 的全网覆盖或长期可用。可在该引擎配置中填写自己的 `CX`，再验证覆盖范围。

修改配置后须重启 SearxNG；新增或改变挂载时须重新执行 Compose up，并分别检查 `/config` 和真实查询。升级镜像须重新验证挂载路径、引擎加载、语言及国际搜索参数，以及 Bing 跳转链接的解析。

### 可用性与限速

实际可用性取决于出口网络、上游限流和验证码。

- **地区**：明确指定地区可以缓解 DuckDuckGo `all` 地区的验证码问题；更换端点不能保证 Bing 始终可用。
- **冷却**：429/拒绝访问冷却 30 分钟，CAPTCHA 冷却 1 小时。当前 DuckDuckGo 适配器的部分验证码分支会覆盖暂停时长，因此仍应避免连续重试。
- **并发**：Worker 通过共享 Redis 控制各引擎，默认并发 1，请求启动间隔 10 秒。可信的 `Retry-After` 更晚时采用更长等待。
- **探测**：冷却结束只允许一个探测，失败再次冷却。DuckDuckGo 受阻时继续使用获准的 Bing/CSE。
- **状态**：跨 Worker 和重启保留。Redis 不可用时停止新的搜索出站，已有证据仍可交付。
- **人工验证**：在浏览器中手动完成挑战的 Cookie 不会同步到 SearxNG，不能保证恢复。
- **说明**：连接池限制不是 QPS 限速；付费 API 费用为零也不代表无限搜索或结果完整。直接打开 SearxNG 或独立烟测会绕过 Worker，共享节流只覆盖受管入口。

### 缓存与预算

- **缓存**：同账号、相同查询与时间范围、实例和引擎组合可复用候选，并合并在途请求。完整响应最多缓存 5 分钟，带缺口的响应最多 1 分钟，空结果和失败不缓存。滚动范围按任务时区每日失效；报告仍逐次读取正文并核验冻结的时间窗口。
- **预算**：缓存命中也占一次逻辑搜索预算，重试另计，缓存不会授予额外的任务额度。
- **默认上限**：每次执行最多 10 次搜索（含重试）；独立连接器默认返回 5 条，Worker 最多 10 条，内部最多选排 30 条候选；搜索词最多 2,000 字符。
- **补搜**：Agent 每读 3 个候选重新选择，余额允许时最多补搜 2 次。
- **请求数**：SearxNG 的一条聚合查询会触达多个获准的引擎，CSE 内部还可能获取 token，所以搜索次数不等于上游的 HTTP 请求数。

### 查询规划

规划优先为不同对象安排互补查询。

- **放宽范围**：精确的 `site:主机/文档路径` 没有有效候选时，可在原预算内放宽到主机，并保留版本与模块词。恢复查询最多 100 个 UTF-16 单位，不增加补搜次数。
- **不当作原文的结果**：同域邮件、其他文档模块或明确不同的版本。
- **多个对象**：共用一个问题时，也按对象检查是否找到候选。
- **标题与 URL 匹配**：只用于发现，不代表所需字段已得到证实。请求 current 或具体版本而来源无法核实时，会保留该限制。

### 部署变量

| 变量                        | 默认值  | 作用                                                         |
| --------------------------- | ------- | ------------------------------------------------------------ |
| `SEARXNG_BASE_URL`          | 见下    | 搜索实例地址，只能由部署者设置，不能来自用户任务或网页       |
| `SEARCH_ENGINE_INTERVAL_MS` | `10000` | 各引擎请求启动间隔                                           |
| `SEARCH_CACHE_ENABLED`      | 开启    | 设为 `false` 关闭候选缓存                                    |
| `SEARCH_ADAPTIVE_ENABLED`   | 开启    | 设为 `false` 关闭补搜                                        |
| `SEARCH_CONFIG_VERSION`     | `1`     | 搜索出口、地区或 CX 改变时，在所有 Worker 同步更新以隔离缓存 |

不要用改版本或清 Redis 的办法反复绕过验证码冷却。每次调用的等待、网络和解析仍受 15 秒硬期限及 Run 剩余时间限制。

`SEARXNG_BASE_URL` 未设置时，主机上的 connector 默认连接 `http://127.0.0.1:8080`。容器内的调用方应通过受控的容器网络连接实例，`127.0.0.1` 始终指当前容器自身。

## 使用 Firecrawl 读取正文

SearXNG 默认用本地 Reader 读取正文。设置 Worker 的 `READER_FIRECRAWL_API_KEY` 可改用 Firecrawl Cloud，留空则使用本地 Reader。

- **本地开发**：使用 `vp run dev` 时，在根 `.env.local` 或 `apps/worker/.env` 配置并重启 Worker。
- **生产 Compose**：把变量配置在 `.env`，更新镜像后用 `docker compose up -d --no-deps worker` 重建 Worker。
- **工作方式**：SearXNG 继续返回候选链接，Worker 把选中的公网 URL 提交给 Firecrawl `POST /v2/scrape`，读取主内容 Markdown。该设置作用于这个 Worker 上的所有 SearXNG 执行。
- **费用与隐私**：Firecrawl 按供应商规则计费，目标 URL 会发送到云端。
- **限制**：单页最多 15 秒，共用执行剩余时间和现有读取预算。禁用供应商的正文缓存复用和写入。失败按来源读取失败处理，单个读取请求不会自动重放，也不会切回本地工具。
- **证据**：正文进入同一工具账本和引用校验。Firecrawl 结果附有独立的提取版本，整页覆盖标为未经验证，供应商元数据不用于认证原站发布时间。Worker 会校验提交与返回地址的公网范围，供应商内部请求与重定向由 Firecrawl 执行。
- **注意**：切换 Reader 可能影响报告的时间窗口验收和历史对比。

## 自定义 HTTP JSON 搜索

在账号搜索配置选择「自定义 HTTP JSON＋本地网页读取」，填写完整的公网 HTTPS 搜索接口地址、独立密钥、请求模板和结果路径。

- **预设起点**：点「填入 Brave Search 预设」，再填写你自己的服务密钥。预设不含免费额度，也没有平台代付承诺。
- **保存**：只校验配置，不发送搜索请求。
- **数量**：一个账号目前只保存一个 API/自定义配置，不支持主备自动切换或多源并行。

### 请求模板

- **方法**：GET 查询参数，或 POST JSON 对象。
- **参数**：扁平的字符串、数字或布尔值，最多 24 个字段。
- **变量**：`{{query}}`、`{{count}}`、`{{language}}`。字符串变量按字段编码，不执行脚本。
- **必有变量**：至少一个查询字段须只依赖必有变量，不能把唯一的 `{{query}}` 与可空的 `{{language}}` 放在同一字段。
- **语言**：未指定语言时，省略含语言变量的字段。语言映射可把标准值转换为服务约定，例如 Brave 的 `{"zh":"zh-hans"}`。
- **密钥**：使用 Bearer 或一个独立请求头，不要写在模板里。

### 结果路径

结果数组路径相对整个响应，链接、标题和摘要路径相对每条结果，支持有限的点号和数组下标。例如 Brave 使用 `web.results`、`url`、`title`、`description`。

响应只产生链接候选。摘要和供应商生成的答案不作为正文或事实支持，随后由本地 Reader 读取并核验原站。

### 限制与说明

- **搜索词**：最多 2,000 个 Unicode 码点。
- **请求**：禁止重定向，默认单次请求，不自动重放付费 POST。
- **不支持**：脚本映射、任意请求头、查询参数鉴权、局域网地址、OAuth 刷新、异步轮询和自定义 Fetch。
- **网络安全**：部署者受信的内网 SearXNG 配置与用户公网接口分开，不能用自定义服务绕过网络安全检查。
- **编辑**：同协议、同地址且模板未变时，可留空保留密钥；改变模板、认证方式、地址或协议须重新填写。
- **运行中修改**：自定义执行在首次装配时冻结配置，正在运行的连接器使用独立副本。恢复时若配置被修改、替换或移除，会明确停止并提示配置已变化，不会静默改用新服务。已有工具或检查点的历史执行不会新增采用自定义服务。

参考：[Brave Web Search](https://api-dashboard.search.brave.com/api-reference/web/search/get)。预设把中文映射为 `zh-hans`，葡萄牙语映射为 `pt-pt`；搜索服务本身的条款、参数和计费以供应商为准。

## 验证搜索

在仓库根目录运行：

```sh
vp run test:search:live        # 一次真实公开搜索，不调用模型
vp run test:search:read        # 另读取首个结果的正文
vp run test:connectors:live    # 搜索、阅读、远程模型原文引用校验
```

- **完整模型烟测**：需要 `MODEL_API_KEY`、`MODEL_NAME`，可选 `MODEL_BASE_URL`。命令不会自动加载或输出密钥，需由启动环境注入。不提供本地模型服务。
- **Tavily**：只通过显式选项使用。实例或上游失败不会切换到收费服务或演示数据。

### 看懂结果

- **`search_passed`**：搜索成功。**`search_partial`**：有缺口。上游验证码、超时、被过滤结果与截断分别记录，全部失败会明确报错。
- **`read_passed`**：才代表采集到了正文。搜索摘要不能当作已读原文。
- **`search_unavailable`**：全部引擎失败且没有可用来源，Worker 日志显示 `TOOL_SEARCH_UNAVAILABLE`。这不表示互联网上没有相关信息。上游状态会随出口和时间变化。

## 网页读取说明

### 支持的内容

- **跳过的格式**：SearXNG 配合本地 Reader 时，HTML 读取候选会跳过 URL 已明确标识的 PDF、办公文档、纯文本和论坛附件，继续选择可读取的网页，不为这些候选消耗读取尝试。显式指定的优先来源或冻结基线不支持时，仍记录覆盖缺口。
- **Search API 模式**：由服务商判断文档提取能力，不套用本地 HTML Reader 的格式筛选。正文仍经读取阶段和工具账本核验，摘要不会升级为证据。
- **字符集**：网页支持字符集解码；格式错误不等于只支持 UTF-8。
- **超限**：可能来自主文档、DOM 或资源的数量和大小。

### 本地 Reader 如何提取

- **优先**：提取主 HTML 中已有的正文，缺少正文时再进行有界的浏览器渲染。
- **保留格式**：保存的文本保留段落、代码换行与缩进、列表和表格的行列分隔。
- **不计为成功**：已识别的验证码、登录门和加载提示。
- **覆盖不完整**：附属资源受限、仅有公开摘要或订阅预览、仍需分页或交互时，保留可核验的正文，并把覆盖标为不完整。
- **限制**：提取在可终止的独立进程中运行；字符数、下载大小和执行时间分别受限，增加正文字符上限不会放开网络预算。

### 读取失败排查

- **`unsafe_url`**：先检查域名是否被代理 Fake-IP 解析成 `198.18.*` 等保留地址。网页读取默认 `READER_DNS_RESOLVER=auto`，仅在系统全部返回 Fake-IP 时，才经 Cloudflare 官方公网引导地址连接其 HTTPS DNS 重新解析，并继续验证、固定每一跳的公网 IP 与 TLS 证书。可设为 `system` 禁用，或显式选择 `alidns|cloudflare|google`。模型通道的默认回退保持独立。请勿关闭私网检查。
- **搜索能用但读不了网页**：搜索实例可以访问，不代表网页正文能被安全抓取。
- **网页 403**：选择公开的替代来源。超时还可能发生在渲染或提取阶段。
- **SearXNG 403**：检查 JSON 格式是否开启及实例的访问控制。容器健康也不代表所有上游引擎可用。
