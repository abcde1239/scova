# 手工配置任务

任务列表选择“新建任务”，或访问 `/tasks/new`。可直接手工填写，也可使用[自然语言草稿](task-draft.md)后显式应用。填写标题、主题与目标，选择查阅时间范围和输出形式；关注事项、排除条件、来源偏好可展开填写，每行一项。预算、任务时区和站内提醒均可查看并修改。执行计划支持[仅手动、每日或每周](task-schedule.md)，默认仅手动；解析建议应用后仍可调整频率、星期和时间。解析和应用仅准备配置。任务可以独立创建、执行和设置周期。

固定范围的日期按界面标明的浏览器当地时区填写，提交时转换为 UTC；任务时区是独立的 IANA 配置。来源只接受无用户名密码的 HTTP/HTTPS 链接；这不等于完成 SSRF 检查或官方身份认证。预算必须为正安全整数，服务端部署策略还可进一步限制。

“资料采集”要求日期窗口，默认近 7 天，仅收录窗口内、有直接原文出处的值，不使用模型补答。日期未知来源可单列或剔除，单列也不计入采集结果。“分析研究”可选不限日期，并允许带【模型自回答】标签的稳定知识回答；回答完成与外部支持分别统计。切换研究方式会设置对应的默认输出形式，之后仍可自行修改；读取已有配置或应用 AI 草稿时保留其明确选择。完成与基线规则见[研究循环](agent-research-loop.md)。

字号、间距、圆角、控件最小尺寸和断点以 rem 为主。日期控件与表单网格允许收缩，在窄屏文字放大时保持操作可达。

确认保存通过统一 requestlane 和同源 Cookie/CSRF 调用 `POST /tasks`，由 `CreateTaskInputSchema` 校验完整配置。「确认保存任务」进入任务摘要。「保存并立即运行」调用 `POST /tasks/start`，在同一事务内写入任务、首版配置、Run、首个事件和 Outbox，并进入执行详情。执行详情可通过任务链接返回摘要。字段错误自动展开所在分组并聚焦，明确失败保留内容；页面离开或关闭有未保存提醒，在途保存阻止应用内路由离开。取消离开可继续填写，实际离开后草稿不持久化。退出或换号会清理旧内容并取消旧账号请求，迟到响应不触发新账号跳转。

每次保存生成一个幂等键。服务端对携带该键的请求去重，同键不同参数返回冲突。网络中断、服务端错误或响应无法校验时，表单保留原内容，可显式重试同一次提交，或返回列表核对。重复点击和自动重试不会发起额外写入。

## 项目归类与继续研究

任务摘要显示当前归属。可以选已有项目归类、在归类时新建项目、换项目或取消归类。归类只更新项目与任务的关系，任务的配置、计划、执行历史和报告依然可从任务入口访问。

从任务摘要选择「继续对话研究」时，已归类的任务会打开所属项目的对话。未归类的任务先显示项目选择，确认归入已有项目或新建项目后进入对话。项目对话可按需选择引用的报告。

## 在项目内创建

在项目详情的「研究任务」选择「新建任务」，进入同一份配置表单。「确认保存任务」创建并关联任务，「保存并立即运行」还会排队一次真实研究，并导航到执行详情。项目接口要求提供幂等键，任务、首版配置、项目归属、可选执行及其排队事件一起提交。在项目概览可查看整个项目中最早的已启用周期计划，以及近期执行和报告。

项目工作台支持多条会话。直接说明想研究的问题或要查阅的报告，项目 Agent 会提议相应动作。确认研究计划后可在会话看到运行状态及结果。原项目详情仍可进入旧版对话，读取默认会话的历史并编辑旧草案。周期仍可在任务表单中直接配置。

验证可运行 `vp -C apps/web test tests/task-create.test.ts`、`vp test --config tests/projects.vite.config.ts` 及 `vp exec playwright test --config tests/e2e/playwright.config.ts tests/e2e/projects.spec.ts tests/e2e/task-create.spec.ts`。项目接口测试使用隔离 PostgreSQL 和 Redis。浏览器用例通过 HTTP 夹具验证页面操作与失败恢复。

## 编辑已有任务

任务摘要中的“编辑任务配置”进入 `/tasks/:taskId/edit`。页面读取当前完整配置和原样 ETag，通过同源 `PATCH /tasks/:taskId` 携带带引号的 `If-Match` 保存完整配置。每日或每周计划可明确编辑频率、当地时刻和星期；未修改时保留原计划。未编辑字段保留原配置内容，固定日期只在实际修改时按浏览器当地时区转换，未改日期保留原始精度。无法识别的配置或不一致的版本/ETag会阻止编辑，避免丢失字段。

发生修订冲突时，草稿仍可复制，停止直接重发。可以先复制要手动合并的内容，选择“重新读取最新版本”，再明确确认丢弃草稿；取消或重新读取失败保留原草稿和修订依据。网络中断或不确定保存结果同样需要先读取核对。写请求不自动重试。

修改成功后停留编辑页，展示服务端实际返回的基线提示。语义查阅范围变化时，下一次完整执行建立新基线；保存不启动执行，也不改写旧执行或报告。可通过“返回任务摘要”继续查看原任务入口。存在未保存修改时，离开、关闭或切换编辑任务会提示；在途写入阻止应用内离开，退出或换号清理旧草稿并取消旧请求。

编辑验证：`vp test apps/web/tests/task-edit.test.ts`；浏览器样本见 `tests/e2e/task-edit.spec.ts`，统一浏览器门禁后续接线。样本不能代替真实数据库的双标签修订冲突验收。
