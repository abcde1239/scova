# 手工配置任务

任务列表选择“新建任务”，或访问 `/tasks/new`。填写标题、主题与目标，选择查阅时间范围和输出形式；关注事项、排除条件、来源偏好可展开填写，每行一项。预算、任务时区和站内提醒均可查看并修改。首版仅保存手动计划，不调用草稿模型，不自动创建或启动 Run。

固定范围的日期按界面标明的浏览器当地时区填写，提交时转换为 UTC；任务时区是独立的 IANA 配置。来源只接受无用户名密码的 HTTP/HTTPS 链接；这不等于完成 SSRF 检查或官方身份认证。预算必须为正安全整数，服务端部署策略还可进一步限制。

字号、间距、圆角、控件最小尺寸和断点以 rem 为主。日期控件与表单网格允许收缩，在窄屏文字放大时保持操作可达。

确认保存通过统一 requestlane 和同源 Cookie/CSRF 调用 `POST /tasks`，由 `CreateTaskInputSchema` 校验完整配置。成功失效当前账号的任务 Query 并进入真实任务摘要。字段错误自动展开所在分组并聚焦，明确失败保留内容；页面离开或关闭有未保存提醒，在途保存阻止应用内路由离开。取消离开可继续填写，实际离开后草稿不持久化。退出或换号会清理旧内容并取消旧账号请求，迟到响应不触发新账号跳转。

每个确定的保存动作持有稳定幂等键，内容不变的明确失败重试复用该键；双击不会并行提交，写请求不自动重试。当前创建任务后端尚未使用幂等键去重，因此网络中断、5xx 或成功响应无法校验时，界面保留填写内容并锁定直接重发，提示先到任务列表核对。不能把请求带有幂等头说成已经提供服务端恰好一次保存。

验证：`vp test apps/web/tests/task-create.test.ts` 覆盖完整配置、校验、取消/账号隔离、幂等键、定向失效和离开决策。运行 `vp exec playwright test --config tests/e2e/playwright.config.ts tests/e2e/task-create.spec.ts` 验证持久浏览器样本，由 Playwright 拦截本地契约样本，涵盖六宽、200%文字、键盘、字段错误、保存、离开和重复点击；这些样本不是实际后端验收记录。

任务摘要中的“编辑任务配置”进入 `/tasks/:taskId/edit`。页面读取当前完整配置和原样 ETag，通过同源 `PATCH /tasks/:taskId` 携带带引号的 `If-Match` 保存完整配置。每日或每周计划保留原频率、时刻和星期；本页不提供计划控制。未编辑字段保留原配置内容，固定日期只在实际修改时按浏览器当地时区转换，未改日期保留原始精度。无法识别的配置或不一致的版本/ETag会阻止编辑，避免丢失字段。

发生修订冲突时，草稿仍可复制，停止直接重发。可以先复制要手动合并的内容，选择“重新读取最新版本”，再明确确认丢弃草稿；取消或重新读取失败保留原草稿和修订依据。网络中断或不确定保存结果同样需要先读取核对。写请求不自动重试。

修改成功后停留编辑页，展示服务端实际返回的基线提示。语义查阅范围变化时，下一次完整执行建立新基线；保存不启动执行，也不改写旧执行或报告。可通过“返回任务摘要”继续查看原任务入口。存在未保存修改时，离开、关闭或切换编辑任务会提示；在途写入阻止应用内离开，退出或换号清理旧草稿并取消旧请求。

编辑验证：`vp test apps/web/tests/task-edit.test.ts`；浏览器样本见 `tests/e2e/task-edit.spec.ts`，统一浏览器门禁后续接线。样本不能代替真实数据库的双标签修订冲突验收。
