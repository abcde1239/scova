# 完整工作台验收

`vp run verify:mvp-full` 先运行[基础 Web 门禁](browser-testing.md)，再串行执行补充页面矩阵与完整用户旅程，最后恢复生产构建。需要 Docker Engine、Compose v2、锁定版本的 Chromium；普通验收不需要远程模型或搜索凭据。`vp run verify:mvp:browser` 只运行补充两项，供 `ready` 在基础门禁之后调用，避免递归和重复静态检查。

## 联合旅程

`tests/e2e/full-workbench.spec.ts` 从真实交付报告开始，完成反馈、下一轮重要费用变化、收藏、笔记创建与真实修订冲突、中文检索、来源快照、四种报告形式、报告内问答和显式关联研究。两个账号验证笔记、来源、问答和检索隔离；四形式共用同一报告和全部证据，切换没有写请求。

笔记冲突由另一次真实 API 写入产生，页面旧 ETag 保存必须返回 409，本地稿经过重新读取和明确保留后才能保存。`known` 反馈不能遮蔽重要新值；历史报告保持原样。提问和取消确认不增加 Run；明确确认只创建一个继承父执行版本、模式和预算的关联 Run，不修改原任务计划或普通基线。

默认 API 没有模型，必须诚实显示 `model_unavailable`。随后仅该隔离项目的 API 使用已有 `acceptanceQuestionModel` 测试入口，验证证据回答的授权引用、独立预算与真实持久化。测试入口拒绝非验收 schema 和远程凭据；生产入口没有此开关。该供应商不会联网，报告及附件的 `remoteResearch: false` 不代表远程模型研究成功。

## 补充页面矩阵

`tests/e2e/supplementary-visual.spec.ts` 在 1440、1024、768、390、360、320 宽度与 100%/200% 根文字尺寸下，检查四主色的浅暗主题、完整和部分报告的四形式、双方引用、收藏与笔记、实际中文搜索结果、快照正文、任务和报告历史，以及问答确认弹层。用键盘展开引用、编辑笔记、提交检索、撤销反馈和取消后续研究；弹层页脚及正文须可达，页面没有整体横向溢出。

根文字尺寸放大不是整页浏览器缩放；桌面 Chromium viewport 不是实体手机。实际读屏、系统软键盘、安全区和横竖屏须分别记录，不能从矩阵截图推断通过。实体设备范围见[移动验收计划](mobile-acceptance-plan.md)。

## 结果与失败

每次聚合运行在 `artifacts/verify-mvp-full/<运行标识>/` 保存命令日志、Playwright JSON、失败截图和 trace、阶段耗时及最终 `summary.json`；基础门禁结果另在 `artifacts/verify-web/`。门禁逐测试要求一次成功、无跳过或重试掩盖，并核对该测试的专属容器、卷与网络清理附件。失败向命令和 CI 返回非零，恢复生产构建失败同样不能标为成功。

`ready` 顺序保留原后端集成与契约检查，再运行基础浏览器和补充工作台门禁。CI 的 Web job 执行完整聚合，受控失败 job 验证非零传播与清理证据；产物无论成功失败均上传。只有实际运行的准确提交结果，才能用于判断对应 Issue 的验收状态。
