# 本地一体化运行与分发计划

状态：方案评审，2026-11-01，对应 [#87](https://github.com/abcde1239/scova/issues/87)。Web 基础验收 [#24](https://github.com/abcde1239/scova/issues/24) 尚待完成；本文提供候选比较与实验计划，不表示桌面端已交付或本项已验收。目标操作系统、容器依赖、分发方式与关窗行为仍需决策，尚未选择 Tauri 或 Electron。

## 当前基础

现有[单机 Web 部署](../guides/deployment.md)使用同源代理、API、Worker、PostgreSQL 17、Redis 7，以及可选搜索服务。Compose 默认只在 loopback 发布代理端口，数据库与队列不发布宿主端口；迁移先于应用启动。浏览器消费静态前端，现有镜像需要容器运行环境。

PostgreSQL 保存业务事实、交付记录与 Agent checkpoint；Redis 队列可通过 Outbox 和恢复扫描重建。Worker 停止时阻止新领取、等待在途操作，再关闭资源。关闭网页可以保留后台执行；关闭整个本地服务后，不承诺继续周期研究。新执行统一真实研究，读取已有报告不触发研究服务。

## 候选架构

| 候选                    | 可复用部分                           | 新增工作与主要取舍                                                      | 必须实验的边界                                  |
| ----------------------- | ------------------------------------ | ----------------------------------------------------------------------- | ----------------------------------------------- |
| 浏览器 + Compose        | 当前 Web、代理、容器、迁移与维护工具 | 需要 Docker/虚拟化；补启动引导、健康检查、端口与日志管理                | 首次安装、端口冲突、显式停止、重启恢复          |
| 浏览器 + 原生服务管理器 | Web 与同源 HTTP 接口                 | 分平台安装和监管 API/Worker/PG/Redis/搜索，管理版本、许可与路径权限     | 依赖分发、进程树退出、数据库升级与故障清理      |
| Tauri + 服务管理器      | Web 界面，可使用 sidecar             | 新增 Rust/权限桥接；系统 WebView 存在平台差异；每个目标架构需要对应程序 | WebView 会话/SSE、最小权限、sidecar 打包与停止  |
| Electron + 服务管理器   | Web 界面，Chromium 渲染环境          | 新增 main/preload/renderer 隔离、Chromium/Node 更新、签名与包分发       | 同源会话、导航/IPC 隔离、服务退出、更新失败恢复 |

框架选择不会消除 PG、Redis、搜索和数据迁移。当前未测候选包体、内存、启动时间或跨平台兼容性；这些指标须在相同测试任务和机器条件下比较。

## 待确认的产品选项

| 选项       | 当前状态与决策内容                                                         |
| ---------- | -------------------------------------------------------------------------- |
| 系统与分发 | 待决：目标 OS/架构、最低版本、是否接受 Docker、安装包或应用商店渠道        |
| 关窗与托盘 | 待决：关窗退出还是驻留；后台运行和潜在远程费用须可见，显式退出始终可达     |
| 通知       | 待决：只保留站内通知，还是请求系统通知；授权、静默、去重与点击定位分别验收 |
| 快捷键     | 待决：是否需要全局快捷键；默认沿用页面键盘操作，不能先占用系统组合键       |
| 文件权限   | 待决：导入、导出、备份需要哪些目录；默认无任意文件访问或 renderer 文件权限 |
| 离线阅读   | 待决：是否允许本地缓存已有报告、缓存范围与退出账号后的清理；不承诺离线研究 |
| 更新       | 待决：手动或自动更新、签名与发布渠道；任何方案均需数据库备份和失败恢复实验 |

## 生命周期与数据边界

| 阶段     | 预期行为                                                   | 最小验收                                                           |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| 安装     | 核 OS/架构、依赖和权限；选择应用私有数据目录；生成独立凭据 | 不使用未知既有数据库；日志不含凭据；程序与数据目录明确区分         |
| 启动     | 实例锁 → PG/Redis 健康 → 迁移 → API/Worker → 同源代理 → UI | 依赖失败不显示就绪；只清理本次新建资源，保留用户数据与诊断         |
| 关窗口   | 按产品决策停止服务，或明确显示后台继续                     | 用户能判断周期任务与远程费用是否仍可能发生                         |
| 显式退出 | 停新调度/领取，收敛在途工作，关闭流、HTTP、队列和连接      | 有界停止；重复退出安全；无遗留子进程；强杀后按租约恢复且不重复交付 |
| 升级     | 旧版本备份、停应用、核结构/迁移账本、迁移、健康读回        | 失败保留备份；不假定迁移后可直接降级；历史 SQL 不改写              |
| 卸载     | 程序与数据分开处理，默认保留数据与备份                     | 删除数据须明确选择和核对目标；不以卸载重置未知目录或共享队列       |

配置、PG 数据、Redis、搜索缓存、日志和备份应分开管理，以用户权限限制访问。备份与恢复继续遵循[维护约定](../guides/deployment.md#备份与恢复)：升级前备份，完成后原子发布，恢复到独立空库，核任务、报告、引用、基线与 checkpoint 后再启动。Redis AOF 不能代替 PG 备份；账号删除也不追溯擦除离线备份。

## 同源与权限

- 保留同源 Cookie、Origin/CSRF 和账号隔离；loopback 端口本身不提供身份认证。启动器须核服务身份与版本，不能连接任意占用端口的 HTTP 服务。
- `APP_ORIGIN` 必须与客户端实际源一致。localhost Secure Cookie 例外、IPv4/IPv6、动态端口及 custom scheme 分别实测；保持 Secure/HttpOnly，不通过放开 CORS 或另存登录 token 规避问题。
- 模型和数据库凭据只留服务端，不进入 renderer、前端包、URL 或日志。保留统一 HTTP/SSE 入口，不因套壳增加第二套业务协议。
- 来源内容仍作为不可信数据呈现，不执行原始 HTML，不获得文件或 shell 权限。外链协议、外部浏览器和最小 IPC 能力须明确；Reader 的私网/loopback 防护保持有效。

## 最小实验与决策顺序

实验仅使用专属临时目录、数据库、队列和卷；每项独立保留版本、步骤、日志、计数与清理结果。

| 任务                | 前置                | 可复现步骤与验收                                                                                                 |
| ------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------- |
| L1 支持范围决策     | #24；产品确认       | 确认 OS/架构/最低版本、是否接受 Docker、分发渠道、关窗/托盘/退出、数据目录和离线阅读需求；逐项标支持或待决       |
| L2 单 OS 启停实验   | L1                  | 全新临时目录启动并核验缺配置错误；分别注入缺依赖、端口占用和中途启动失败；退出/再启，核数据保留与无遗留端口/进程 |
| L3 会话与隔离实验   | L1，选取候选        | 登录、SSE 断线续传、重启、端口冲突、未授权源写与外链打开；核 Cookie/CSRF、服务身份及 renderer 无密钥             |
| L4 数据升级恢复实验 | L2                  | 临时旧库写任务/报告/笔记，备份后升级；注入迁移失败；恢复独立空库，核引用/基线/checkpoint、单次交付和原库未改     |
| L5 打包与更新比较   | L2/L3；分发渠道确认 | 制作单 OS 候选包，记录包体/启动资源/许可/签名要求；验证升级中断、旧版本兼容与卸载保数据                          |
| L6 实现拆分         | L2–L5；平台决策     | 按启动、数据、分发、界面拆独立任务；每项有依赖、失败路径和验收，控制在半日或 10 文件以内                         |

L1 的实质性选项确认后再开展平台实现。本文不新增 PWA、原生移动、系统推送或离线研究承诺，也不把本地一体化作为 Web 发布前提。
