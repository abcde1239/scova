# Web 会话恢复

启动时通过统一 requestlane 的 `/me` 恢复 Cookie 会话，受保护页面在恢复完成前不挂载。401进入登录；暂时断网、超时或503在独立 /service-unavailable 页面展示可重试状态，并保留已有内存会话和原路由（含查询和片段）。认证页同样先完成服务检查；重试为401时进入登录，不短暂挂载业务页。首次路由确认前只显示独立加载布局，没有工作台导航。已登录后的业务导航也在提交路由前重新核验 `/me`，避免后端断开或会话过期后先进入目标页。同账号且 CSRF 未变时保留缓存和订阅，身份或凭据变化仍推进 epoch。账号、Query缓存与流清理由既有epoch生命周期负责，客户端不读取HttpOnly Cookie或保存JWT/CSRF。

登录后只返回当前路由器可识别的站内目标，认证页、未知页、协议地址、反斜杠及畸形编码回退任务页。全局工具提供退出；成功清理账号上下文，失败保留账号并提示重试。旧账号的迟到响应不得影响新账号。生产环境没有测试服务或测试认证开关。

`vp run test:e2e tests/e2e/session.spec.ts` 验证恢复、过期、暂不可达重试、退出/后退与账号隔离。浏览器回归使用 `tests/e2e/serve.mjs` 的生产资源预览和明确标识的本地HTTP样本；单个测试可覆盖响应，它不代表真实账号服务。全栈验收使用独立真实API/数据库环境。

状态、按钮和错误使用共享组件与弹性尺寸；200%文字放大与真实浏览器整页缩放分别验收。

Run 的连接状态、持久游标恢复和页面订阅方式见 [Run 事件订阅](frontend-run-events.md)。
