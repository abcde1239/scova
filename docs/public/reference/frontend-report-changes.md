# 报告变化与基线

四种成果共用 `ReportChanges`。生产成果面板在正文前显示变化区，先显示比较状态，再展示新增、实质变化和待核验；重复、疑似转载及非实质变化收在“其他 N 项”中。首次满足条件的执行显示“已设为比较起点”，不重复列出基线事实。未满足条件时显示“未设为比较起点”及具体原因，例如字段仅有模型回答、外部证据不足或日期未确认。

回答完成与比较起点资格分别保存。新执行的 `coverage.baseline` 表示资格与原因，全部必答字段有外部支持且完整性和比较检查通过后才推进起点。模型答案不计外部支持；历史报告缺少该字段时沿用原有 outcome 和完整性判断，不凭空补充资格。策略详见[研究循环](agent-research-loop.md)。

服务端可返回已授权的 `baseline` 报告摘要，页面据此链接上次报告；仅有 `baselineRunId` 时链接上次执行。所属账号、任务、模式与范围由 API 校验，前端不自行拼接任意报告关系。

每项保留原事实键、重要性和原因，以“旧值 → 新值”显示，旧值为空时仅显示本次值。两侧引用分别定位集中保存的原文，不借用另一侧证据。`null` 不表示删除、撤回或无变化；旧值存在但没有旧引用时继续显示待核验。

分类和重要性沿用报告，页面不重新计算事实。只有服务端给出 `no_important_change`，查阅完整且没有重要项、待核验或缺失的旧值证据时，才显示“无重要变化”。partial、空变化数组或本次未观察到某页都不能证明资料没有变化。

引用归属与旧新侧由 API 校验。返回 `409 INVALID_REPORT_EVIDENCE` 时整份报告隐藏并提供重新读取入口，不展示部分失败引用。页面不重新抓取来源或推进基线。

```sh
vp test apps/web/tests/report-changes.test.ts
vp run test:e2e tests/e2e/report-changes.spec.ts
```
