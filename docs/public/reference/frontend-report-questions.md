# 报告连续对话

报告详情以原报告为对话锚点，保存有序问答。普通提问结合报告、最近对话及更早的简要记录，只查阅当前报告已保存、授权的证据。生成新版与联网补充是需要独立确认的操作，见[报告修订与后续研究](frontend-followup.md)。原报告的演示、部分交付与覆盖缺口仍按报告原样展示。

## 提问与保存结果

问题保留原始空格与换行，最多 2000 个 UTF-16 码元，纯空白不能提交。提交后本次问题和幂等键固定；未确认结果时，使用“读取本次结果”明确恢复。网络错误、处理中或限流并不证明服务端未保存问题，恢复沿用同一问题和键，不自动重试写请求。

空白问题可通过“总结主要发现”或“查看结论依据”填入建议，填入后可继续编辑，点击“提问”才提交。成功后清空已提交输入，可直接继续追问。历史按轮展示问题、回答、引用和关联执行，选中一轮可查看用量及后续操作；工作区收起对话时保留草稿及未确认请求。

服务提供 Retry-After 时界面显示再次读取时间。读取可能返回已保存的不足结果，不代表再次调用模型。结束未知请求前应复制需要保留的问题；服务端可能仍已处理，再次独立提问可能另计用量。切报告、换号或卸载会中止客户端请求，不能撤销已经执行的模型调用。

刷新先读取当前授权报告，再 GET `/reports/:reportId/conversation` 恢复最近100轮；“查看更早的对话”用 `beforeQuestionId` 向前分页。处理中轮次和活动的关联执行按需轮询，过期未完成问题由服务端收束为中止状态。链接的 `questionId` 定位指定回答，不再次 POST 或调用模型。问题正文和幂等键不写入链接或本地存储，未发送草稿仅保存在当前页面。

发送时固定 `afterQuestionId` 和幂等键。另一标签页已新增轮次时返回冲突，需读取最新历史后再明确提交，避免把新问题接到过时上下文。每份报告独立排序，同一报告同时只能处理一轮，历史接口和游标都按账号与报告授权。

模型使用原生 user/assistant 消息：最近最多12个完整问答，更早最多16轮保留带问题标识的截取摘要，同时携带有界报告内容和最多24条保存证据。输入还受 token 预算裁剪，不保证永久记住全部细节；久远或含糊的指代应写明具体内容。历史回答仅作讨论上下文，不成为新的事实证据。

## 回答与不足

每条回答必须带当前报告的证据 ID，引用必须是保存原文中的连续逐字片段。事实摘录要求逐字匹配，解释与归纳允许自然语言并明确标识；逐字引用通过不代表已经完成语义支持或真实性核查。身份、结构、状态或引用校验失败时不显示回答。证据可用键盘展开，HTML 与 Markdown 按纯文本展示。

不足状态区分证据不足、未配置可用模型、模型失败、输出未通过核验与中止。需要更多资料不表示已同意启动后续研究；关联后续执行须通过面板中的独立确认操作，见[后续研究](frontend-followup.md)。

模型尝试与输入、输出 token 是本次问答的独立记录，不计入原 Run 预算。包含估算或未知调用预留时明确标注，不表示精确费用或实际扣款。

当前报告暂时不可读，包括同账号的权限或不存在响应时，已输入的本地问题与未确认请求保留供复制；回答、引用及读写暂停。换账号或换报告清除旧编辑上下文。离开未提交或未知请求前有确认，已保存回答可通过其链接恢复。

## 验证

`vp test apps/web/tests/report-questions.test.ts apps/server/tests/report-conversation.test.ts` 检查契约、引用、有界上下文和隔离。浏览器专项使用 `vp exec playwright test --config tests/e2e/playwright.config.ts tests/e2e/report-questions.spec.ts`；数据库与真实Worker专项使用 `tests/report-questions.vite.config.ts`。受控模型测试不代表真实付费供应商的回答质量。
