# 两次执行验收场景

本文用三类任务演示“首次执行 A、第二次执行 B”的可复现验收：A 完整交付后成为基线，B 在同一比较范围与模式下运行，检查新增、重复、变化和异常的处理结果。数据模型见[数据模型](../reference/data-model.md)。

所有站点使用 `example.org` 占位，页面内容由固定 fixture 提供。验收应读取结构化结果与数据库数量，同时核对页面展示。

## 通用流程

1. **前提**：准备固定 fixture（A、B 两组页面输入），任务配置按各场景给出。
2. **步骤**：执行 A，确认完整交付并建立基线；再执行 B。
3. **预期结果**：对照各场景表格检查分类、引用、基线推进，以及 report/Inbox/Notification 数量。

## 场景 1：免费 B1 英语听力材料

**前提**

- 任务：“每周寻找适合 B1 水平、带字幕的免费英语听力材料，避免重复推荐。”
- 关注难度、字幕、费用和可用性；排除付费/明显超出水平内容；输出主题清单。

**步骤**：按下表准备 A、B 输入，依次执行 A 与 B。

| 资料              | A 输入         | B 输入                        | B 预期                                      |
| ----------------- | -------------- | ----------------------------- | ------------------------------------------- |
| /english/lesson-1 | B1、字幕、免费 | 相同正文，URL 多了 utm_source | duplicate；不再次推荐                       |
| /english/lesson-2 | B1、字幕、免费 | 同 URL 改为必须付费           | changed；旧/新费用证据，标为不再符合目标    |
| /english/lesson-3 | 未出现         | 新增 B1 字幕免费材料          | new；推荐并引用原始页面                     |
| /mirror/lesson-1  | 未出现         | 与 lesson-1 正文一致的转载    | duplicate_candidate；保留来源，不冒充新材料 |
| /english/advanced | 未出现         | C1、无字幕                    | 排除；筛选记录可解释，不计为推荐新增        |

**预期结果**

- A 建基线。
- B 推荐新材料 1 条、实质变化 1 条，重复和疑似转载可查看。
- 排除材料不计为用户成果。
- 反馈“已了解 lesson-1”不会屏蔽 lesson-2 的费用变化。
- “希望深入”在下一次计划中产生可追踪的子查询。

## 场景 2：官方招生通知

**前提**

- 任务：“定期查阅指定院校的官方招生通知，突出报名条件和截止日期变化。”
- 配置官方域名偏好和每周时区计划，输出对比表。

**步骤**：按下表准备输入，依次执行 A 与 B；再执行补充执行 C。

| 资料                   | A 输入                      | B 输入                      | B 预期                                       |
| ---------------------- | --------------------------- | --------------------------- | -------------------------------------------- |
| /admission/notice      | 截止日期 11 月 15 日；需 B1 | 截止日期 11 月 22 日；需 B2 | changed；展示两组旧/新值及双方引用，重要变化 |
| /admission/faq         | FAQ 正文                    | 仅导航时间戳变化            | duplicate/non_material；无重要提醒           |
| /admission/scholarship | 未出现                      | 新奖学金通知                | new；按目标相关性展示                        |
| /blog/repost           | 与官方 notice 相同内容      | 仍保留旧截止日期            | 作为冲突转载标记，优先官方原文并解释         |

**预期结果**

- changed 不会因为 B 的内容与其他 URL 指纹一致而被判为重复；同 URL 的事实变化先比较。
- 报告有两组旧/新值及双方证据。
- 重要变化偏好最多产生一条 important_change 提醒。
- 任务中心正确显示用户当地下一次运行时间。

**补充执行 C**：官方通知抓取失败，其他页面成功。

- C 交付 partial 或证据不足失败。
- 不能写“报名条件无变化”，不推进 B 的完整基线。
- C 未观察到某条旧通知，不推断撤回。

## 场景 3：研究方向与不同观点

**前提**

- 任务：“持续关注某研究方向，整理新进展、不同观点和原始资料。”
- 优先论文/机构原文，输出研究报告。

**步骤**：按下表准备输入，依次执行 A 与 B。

| 资料               | A 输入            | B 输入                   | B 预期                                             |
| ------------------ | ----------------- | ------------------------ | -------------------------------------------------- |
| /papers/a          | 论文 A 原文       | 相同正文                 | duplicate                                          |
| /news/a            | 论文 A 的新闻介绍 | 仍为同一介绍             | 保留次级来源关系，不作为独立新研究                 |
| /papers/b          | 未出现            | 新论文 B，结论与 A 不同  | new；说明实验条件和观点差异，引用两份原文          |
| /papers/a-revision | 未出现            | 作者修订，明确更正样本量 | new + 与原论文的修订关联；更正内容标为重要事实变化 |

**预期结果**

- 新论文的不同结论呈现为 conflict/不同观点，不自动判定 A 已被推翻。
- 报告区分来源事实、推断和证据不足。
- 新闻重复不增加“独立证据数量”。
- 无法获取论文正文时，引用可访问的摘要并标明覆盖限制。

## 一致性与异常矩阵

| 条件                                        | 必须观察到的结果                                     |
| ------------------------------------------- | ---------------------------------------------------- |
| 连续执行 B 两次请求使用相同 Idempotency-Key | 同一 Run、同一响应引用，无新报告/提醒                |
| 相同 key 不同配置 payload                   | 409，不重用错误响应                                  |
| 两个 worker 同时领取同任务                  | 只有一个有效租约；唯一索引阻止第二个活动 Run         |
| job 被重新投递                              | 已终结 Run 直接结束，不重复交付                      |
| 报告事务提交后 worker 未 ACK 就宕机         | 恢复后报告/Inbox/Notification 数量不变               |
| checkpoint 已写，业务引用未提升即宕机       | 从最后已提升 checkpoint 恢复，不信任未提交状态       |
| 旧 worker 在新 epoch 后提交                 | 所有业务写入被 fencing 拒绝                          |
| 调用供应商后、保存结果前宕机                | unknown 调用仍计预算；重查必须有新调用记录           |
| 暂停周期计划                                | 无新计划 Run，当前执行可正常结束                     |
| 用户取消与交付同时发生                      | 行锁决定唯一终态；取消先获锁则无报告                 |
| 搜索/阅读/token/时间预算耗尽                | 停止外部调用；有证据可确定性交付 partial，基线不前移 |
| 外部服务临时错误持续发生                    | 有限重试且计预算；不自动切换演示                     |
| 仅配置标题或提醒变化                        | 配置版本变化，比较范围不变                           |
| 改主题、关键来源范围或模式                  | 新比较范围建立基线，旧报告可查                       |
| SSE 在 seq N 后断开并重连                   | 回放 N+1 起的事件，无缺口；前端去重且终态一致        |
| 第二账号访问任意资源 ID/事件/关联引用       | 返回 404 或拒绝创建非法关系，无数据泄漏              |

**DST 固定测试**：

- America/New_York 每日 02:30 在 2026-03-08 跳时日顺延到 03:00。
- 每日 01:30 在 2026-11-01 回拨日只取较早一次。
- 以锁定时间库的实际 UTC 输出断言，避免使用测试机器时区。
- 停机多天仅补最近一次到期时点，活动执行时记录 skipped_overlap。

## 完成标准

- 三个场景的预期分类、引用、基线推进、report/Inbox/Notification 数量均有自动断言。
- 演示与真实运行分开报告。
- 图测试覆盖分类和引用；PostgreSQL 集成覆盖基线推进、不完整执行、原子交付、通知、调度和反馈。
- 真实烟测另选可控公共页面，不以互联网上不可预测的更新作为回归条件。
